# Sokoun professional features — manual QA

Automated coverage and its results are recorded in [the completion report](sokoun_professional_features_report.md). The device/staging scenarios below remain manual acceptance checks. Use test accounts and an approved staging deployment; never use production mutations for verification.

- **Listing drafts:** create an incomplete draft, reorder/caption public photos, leave, terminate the app and reopen. Continue restores values; Discard removes the draft. Delete one managed media file and confirm only that file requires reselection. Ownership proof must require reselection and must never appear in the managed public-media directory. Editing locally must not PATCH or reset moderation.
- **Conflicting edits:** save an edit draft, change the property through another authorized client, then reopen and submit. Fresh owner details must load and the user must review the conflict before another explicit submission. Verify retained image IDs, cover order, removals and the current photo/video validation rules.
- **Partial upload:** interrupt after create and two confirmed images. Reopen the same property and inspect progress. Known IDs must survive; the same property must be used. Simulate a lost acknowledgment: show an unknown outcome and retain the draft without blindly retransmitting. Sending/unknown photos cannot be removed to hide the unfinished operation. Retry a definitely rejected file explicitly.
- **Local storage failure:** make protected storage or the media budget fail. Show an unsaved warning, retain input/leave protection, then restore storage and retry. Never show Saved locally while a write has failed.
- **Discovery:** load Home/search/details, go offline and return. Public saved content must remain readable with contextual feedback. Switch language/environment and confirm cache isolation. A refreshed 403/404/410 must remove inaccessible content; a transient failure must retain usable content. Fail page two and retry without dropping page one, duplicating items or skipping a page.
- **Favorites:** rapidly save/unsave in details, switch to Saved, and deliver an old list response. The newest intent must win. Undo performs a real re-save; a failed final request restores the confirmed baseline. Repeat for two offers in one property and for unrelated properties.
- **Search:** type quickly and change filters before a response returns. Older results must not replace the current search. Open details/back and switch tabs without losing context. Relaunch, use Continue your last search, and verify filters/loaded context/scroll restoration. Save, rename, delete and reapply a search; remove a catalog choice and verify the correction notice. Recent searches remain limited to five and isolated by account/environment.
- **Viewing/reviews:** recover a stale date/time and keep the note while correcting the selection using fresh tenant availability. Reject past Cairo times, including DST boundaries. Fail or time out submission and verify there is no automatic rebooking. Open a review notification with a real visit ID; load fresh details and open the rating form only when currently eligible. Missing, malformed, forbidden and already-reviewed visits must not open a broken submission form.
- **Owner schedule:** enter availability directly from an owned property with no requests. Recover unsaved changes, book/lock a slot elsewhere, then save. Fresh booked/locked slots must remain protected and conflicts require review. A failed save must not show success.
- **Chat:** recover composer text using Continue/Discard. Lose a socket ACK, then deliver it late: the pending item must settle once. With the default replay flag off, no automatic REST resend or restart replay is allowed for unknown delivery. Under the verified replay capability, test FIFO restart recovery and matching UUID/server-ID reconciliation across both transports. History screens stay read-only; loaded history/scroll survive reconnection. While reading older messages with large text and a keyboard, scroll the privacy/contact footer and receive a message: the conversation must retain its reading position. Reporting needs a real supported ticket reference.
- **Destinations:** exercise cold/warm property/offer links, notification-center and push taps, repeated taps, an already-open target, login completion/cancel and owner/tenant workspace changes. Inaccessible/deleted resources must have a useful error state. Test both canonical hosts on signed Android/iOS builds after association hosting is configured.
- **Account cleanup:** with A's drafts, pending sends, saved searches and private screens loaded, log out/expire/remove the session, then sign in as B. A's records, history, pending destinations and late writes must not appear or execute. Repeat while a protected write is in flight. Appearance preferences may remain.
- **Preferences/support/profile:** rapidly toggle supported server subscriptions and privacy settings; the final failure must roll back and remain visibly failed. Locked/required preferences stay enforced, separately from OS permission. Recover supported profile/support text without passwords, OTPs or private attachments; unavailable services must not fabricate success or references.
- **Presentation:** inspect Arabic RTL and English LTR, light/dark/system appearance, keyboard entry, reduced motion and text scales 1, 1.3, 2 at 320, 390, 600, 768, 1024 and 1366 logical pixels. Check touch targets, visible status/retry controls, natural text height and scrolling with a keyboard.
