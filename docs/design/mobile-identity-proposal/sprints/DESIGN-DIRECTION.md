# Visual direction — original proposal is the authority

User feedback: prefer the original S01–S20 style. Sprint 1 was revised to extend those exact screen families. Apply this direction to later sprints after the user's approval.

- Use the original embedded `atlas.css` and fonts as the visual foundation. Preserve its typography hierarchy, warm paper/pine palette, field heights, 12px control corners, 14px cards, original actions, spacing, navigation and phone chrome.
- Account access follows S02: authentic Sukoon wordmark, calm introduction, simple fields. Verification and status screens follow S03/S19: circular status symbol, centered identity/status where appropriate, simple summaries.
- Primary hubs follow S05/S18: forest-green header, actual outlined calligraphic signature, white wordmark, and the original heading proportions. Sprint 1 applies this to profile, notifications and help.
- Forms/settings follow S17/S20: restrained headings, paired related fields where useful, lightly bordered surfaces and original action footers.
- Use architectural arches selectively as in the original. Avoid a new generic arch-shaped icon badge across every screen, oversized menu icons or a separate typography scale.
- Maintain current app behavior, role visibility, permissions and state handling. Style changes do not authorize native implementation or a new sprint.

Every completed sprint manifest entry includes `visualReference` pointing to the original screen IDs it extends. Review [Sprint 2](sprint-02/index.html) and [the revised Sprint 1 atlas](sprint-01/index.html) alongside [the original](../index.html).

These are browser mockups. The original compact metadata sizes are not a native accessibility prescription; follow the native readability contract during implementation.
