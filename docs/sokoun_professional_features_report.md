## Integration limits and deliberately deferred work

**Client-ready, integration-unverified:** platform secure-storage protection and process termination on real devices; live permissions/conflicts, tenant slot/review/support deployment; push and hosted Android/iOS associations; signed builds and OS link dispatch. Local tests do not establish live backend or device behavior. Search offset restoration is best effort when fresh list ordering changes, rather than a guarantee that a removed/reordered item remains at its old pixel position.

**Backend-blocked:** legacy property create/image uploads do not have verified duplicate-safe replay. A lost acknowledgment remains recoverable but unknown. Full-file retry is not byte-resumable upload. Viewing/review/support ambiguous submissions likewise stay preserved rather than automatically retried without operation identity.

A generic transport connection error also remains unknown because it does not prove that a write was never dispatched; a connection-establishment timeout retains its existing pre-connection classification. The core loopback/adapter regression confirms one accepted POST and no automatic replay. This conservative behavior can require authoritative checking even when a disconnected transport supplies little diagnostic information.

The 8 October handoff describes `client_message_id` deduplication across both WebSocket and REST, but staging must demonstrate it. `SOKOUN_CHAT_DURABLE_REPLAY` defaults to **false**. With it off, a lost socket ACK cannot cause an automatic duplicate REST transmission or restart replay. Gated replay is implemented and locally tested; it is not enabled by this task.

**Deferred:** Live Activities, home widgets, biometric app lock, remote logged-in device/session revocation, per-conversation mute, saved-search alerts, cross-device draft sync and chunked upload resume. Existing rental/offers/provider/payment/lease capability gates and business policies are preserved.

See the [manual QA checklist](sokoun_professional_features_qa.md) and the single [backend/native handoff](sokoun_professional_features_handoff.md) for remaining acceptance and proposed contract semantics.
